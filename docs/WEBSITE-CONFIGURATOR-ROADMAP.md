## Client journey
1. Choose a complete website or build a custom page. Browse the real complete-template gallery with actual responsive preview. Exact complete-template choice is a legitimate design reference even when no faithful core-component mapping exists. Optional start-from-layout editing only for explicitly mapped recipes; do not invent component mappings for integrated immersive designs.
2. Guided sections: optional utility/announcement, header, hero, business-relevant content (services, about, galleries, projects, process, trust, articles, menus, products, etc.), CTA/contact/form, footer. User can skip optional categories, add multiple body sections, replace/remove and reorder with accessible up/down controls (drag optional). Header/footer unique by default; overlays/legal and motion are settings or attached to specific section instances, not duplicate body blocks. No forced irrelevant sections. Search, real example preview and selection by permanent ID; retain choices across back/next.
3. Responsive review of selected real examples and composed rough page, using actual CSS viewport widths. Provide phone 320/390/430, tablet 768, desktop 1024/1440 and wide 1920 presets (360/375 optional additional). Show default mobile alongside only compatible implemented alternatives when available. Default is a valid choice and has no invented ID. Apply chosen alternate only at the declared narrow breakpoint; desktop/tablet stay unchanged. Can compare real interactive source examples separately from rough composition.
4. Branding: primary, secondary, optional trim/accent with native picker and validated hex text; no forced third colour. Offer default palettes, reset and live preview. Document semantic roles (primary dominant brand/CTA, secondary surfaces, trim small accents), contrast-aware text, neutral surfaces. Preserve stock images; do not recolour photos. Warn and suggest accessible alternatives when contrast is insufficient; never claim final accessibility from palette alone.
5. Review whole assembled page at each viewport, with coherent placeholder brand/content and honest rough-design label, section order controls, back/edit, confirmation. Complete template mode shows genuine existing layout; recolouring only where palette mappings verified, otherwise clearly label palette as design brief preference. Never silently approximate a full template as unrelated components.
6. Confirm and produce ordered human-readable brief with copy button, selectable manual fallback and optional JSON/text download. Exact template mode includes stable template slug/path and explicitly known mapped IDs only. Custom mode outputs one entry per selected instance, sequential positions, core ID, compatible alternate or default, attached animation IDs, palette hex values. Preserve repeat occurrences and their distinct mobile/animation settings. Changes invalidate prior confirmation.

A. Build standalone mobile-first `components/builder.html` wizard reachable from original gallery, catalogue and review page. Shared canonical read-only catalogue and compatibility data; schema-versioned localStorage draft (recover safely if invalid/unavailable), no login/backend, analytics or submitted contact info. Data model: mode, templateSlug, ordered array of unique instance keys with coreId/mobileTreatmentId/animationIds, palette, confirmed snapshot. Use canonical IDs not titles as keys. Validate against current catalogue on restore and export; handle retired IDs explicitly. Pure reducer and validation/export functions first. Vite multi-entry and static Pages routes, preserve relative base and check production artifact.
B. Build selection and mobile review UI with existing real preview routes, accessible navigation, bounded lazy iframe loading and focus management. Link to real original site/section review; never accept untrusted frame URLs. Full template references come from catalogue discovery; stable template layout recipe map with real verified IDs only.
C. Implement composable specimen adapters: one scoped section from each core preview (showcase focus anchor is useful but not sufficient, especially for mobile menu siblings and shared styling). Strip unrelated demo context and controls, isolate styles/IDs/anchors, normalize content and spacing, support section-owned behavior or deliberate labeled rough approximation. Use single coherent page document with shared theme tokens and responsive rules, not a pile of full-page iframes. Explicit per-ID adapter support; no fallback generic card falsely labeled as exact selected design. For unsupported assembly, clearly mark unavailable/representative preview while retaining genuine source review; require comprehensive verified coverage before claiming all 157 composable. Animations attach to compatible targets. No code execution from client-provided data, no arbitrary HTML injection, no external form submissions. Build deterministic real template recipe mappings separately; integrated cinematic sites remain whole-layout references until extraction is proven.
D. Add colour token mapping and viewport review with no cropped hidden content, real iframe viewport dimensions, scrollable page and mobile alternative comparisons. Native inputs, contrast validation, reduced motion, keyboard and touch.
E. Add confirmation, ordered clipboard/export, manual copy fallback and versioned brief; no checkout/payment/backend or publishing client sites. Optional JSON export for future handoff; no raw source downloads. All confirmation stays local.
F. Test pure reducer/compatibility/order/palette/serialization/draft restoration; browser end-to-end custom and full-layout paths, skip/add/duplicate/reorder, incompatible variants rejected, defaults preserved, actual 320/390/430/768/1024/1440/1920 responsive previews, color application, clipboard and fallback, no unwanted network submissions, invalid data recovery, back/edit/confirmation invalidation, keyboard focus, reduced motion, original gallery/review/build regression. Inspect actual screenshots and real device behavior before release. Resume paused QA, media clearance and experiential extraction after configurator implementation/review; update roadmap and statuses with evidence.

## Non-goals
Not a finished website generator, not a quote engine, not a no-code publishing platform. Rough layout is an informed design brief, not final product; images, copy, integrations, spacing, palette contrast and accessibility remain subject to development/QA. No made-up component IDs or claims that every standalone demo is already composable. No main merge without authorization.
