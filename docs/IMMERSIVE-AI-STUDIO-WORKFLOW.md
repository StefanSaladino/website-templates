# Immersive template development — AI Studio × ChatGPT

Adopted 2026-11-24. Scope: high-ambition experimental templates; simpler commercial sites do not need the entire specialist workflow. `main` is authoritative for GitHub Pages. The stakeholder (Boomer Automation) owns final creative acceptance. AI Studio is a creative prototyping partner, not a deployment authority; ChatGPT coordinates the repository, engineering audit, specialist tests, creative feedback and integration. Both may contribute creatively and technically.

## Repeatable production loop

1. **Brief and clean baseline.** Sync/import current `main` into AI Studio (new window requires a fresh import and repository orientation). Read PROJECT-ROADMAP.md, UI-DESIGN-RULES.md and relevant specialist examples. Define a distinctive experience, a continuous storyboard, independent phone composition and measurable visual targets. Record baseline SHA.
2. **Isolated prototype.** Build only `templates/_drafts/<slug>/`. Modular HTML/CSS/JS/shaders/assets; no shared dependency or catalogue changes without approval. Preserve actual persistent geometry/world, native scroll, reversible motion, accessible static/reduced-motion/graphics-unavailable alternatives. No generic decorative animation or AI design tropes. Export ZIP and architectural notes; AI Studio must not attempt unauthenticated pushes.
3. **Controlled handoff.** Inspect the exported archive and diff only the requested draft against the exact baseline; reject unrelated repository changes and stale overwrites. Verify asset provenance, syntax, dependencies and source integrity. Keep the modular originals (MATTER's standalone draft bundle was a specific preview exception). ChatGPT publishes the isolated draft and dedicated QA changes to `main` after scope verification, with a versioned Pages preview link. Check deployment independently of browser QA.
4. **Engineering and visual evidence.** Audit render lifecycle, native scrolling and camera continuity, reverse progression, intermediate poses, framing and clipping, pointer/keyboard/touch, responsive layouts, no overflow, performance and stable buffer budgets, fallback and recovery. Use actual rendered frames at representative widths (320/390/768/1440 when practical), not merely markup or shader compilation. Record commit, workflow run, assertions, screenshots and failures. Review continuous motion recordings and physical phone feedback; software rendering and static screenshots do not establish real-device frame cadence. Explicitly distinguish passed, failed, pending and untested checks.
5. **Stakeholder review.** Evaluate opening composition, visual subject, movement, payoff and mobile independently. Obtain explicit user acceptance rather than using green CI as a proxy. For example, MATTER's technically passing M3 composition shrank the sculpture and particle field; stakeholder feedback required full-screen dissolution, not stricter bounding boxes.
6. **Choose the revision owner.** If the concept/art foundation is sound and problems are bounded (camera, scroll, shader math, masking, layout, lifecycle), make targeted ChatGPT engineering passes and verify. If the visual foundation is weak (geometry, composition, material realism, lighting, landscape scale), return the current source to AI Studio for an explicit visual overhaul with concrete scene-by-scene criticism, references/targets, creative freedom within scope, and preservation of accepted engineering improvements. Import/export again from the current baseline and repeat steps 2–5. Avoid unproductive incremental polish of a fundamentally weak concept.
7. **Promotion gate.** Only after explicit creative acceptance and passing relevant exact-revision tests, move the approved draft into the registered template path. Capture its real opening viewport, update gallery/thumbnail ledger, catalogue, dedicated immersive test contract and roadmap; verify full build and published route. Gallery-only by default when native configurator palette/expanded-preview interactions are not separately verified. No implied production approval, commercial rights clearance, Safari/device certification or new builder eligibility.

## Review record (per pass)

Record in the project-specific README/REVIEW and summarize in PROJECT-ROADMAP.md: pass ID; owner; input/base SHA; requested design outcome; files/scope; changes; evidence and run IDs; stakeholder reaction; accept/revise/return-to-AI-Studio decision; outstanding technical/visual/device/rights risks; next owner and pass. Preserve prior entries as history and supersede obsolete statuses explicitly.

## Initial applications

- **MATTER M1–M6:** first AI Studio → ChatGPT → stakeholder → iterative engineering case. M2 renderer/fallback, M3 camera/material improvements, M4 full-screen dissolution after user feedback, M5 mobile overlay removal, M6 verified registration. Registered as template 38; gallery-only. See `templates/matter-exhibition/REVIEW.md`.
- **ATLAS A1–A3:** first deliberate return to AI Studio for a major visual foundation overhaul. A1 modular export and depth reset, A2 cleaner map/typography, smoother spline, stable buffers and accessible controls; A2 browser and Pages passed, but stakeholder recording/feedback rejected the initial visual standard. A3 creative brief requests a new cartographic opening, convincing geology, cinematic descent, recognizable lake, summit payoff, integrated archive and portrait-first compositions. Preserve A2 engineering; A3 implementation/export/import not yet received or verified. See `templates/_drafts/atlas-terrain/README.md`.

Principle: **creative ambition → real implementation → measurable evidence → human visual judgement → deliberate iteration.** The visual experience is the product, not a decoration added to a conventional page.
