## Shared structural defects and improvements

1. **Canonical world:** `buildTerrainData(resolution)` regenerates erosion at 10/14 iterations, and detail changes destroy/recreate resources. Small but measured geographic drift and potential stalls. Make erosion/height field invariant across quality, use mesh decimation/resampling and compatible surface queries; preserve lake and named landmarks.
2. **Geological scale:** main mass constructed from ridge envelopes and additive peaks, with lightweight erosion and colour-only forest. No actual trees, foreground rocks, independent geological strata geometry, scree/rock scale. Introduce authored asymmetric peaks, ridges, valleys, directional geological texture/material and sparse instanced native-scale details only where visible. Don't replace persistent world with photographic scene swaps. Establish silhouette and daylight look before expensive effects.
3. **Material and light pipeline:** terrain, water, reflected mountain colour and sky use different shading/tone-map curves. Match shared linear light/exposure and atmospheric perspective. Existing A7 angular micro-normal attenuation covers bump only; high-frequency canopy stipple, strata and shore masks still risk aliasing. Validate close and distance textures, snow/slope/accumulation, contact shadows, exposure and material palette in actual frames. Far terrain extent is 220 units with 340-unit far plane; boundary visibility must be measured, not assumed.
4. **Surface coherence:** mesh triangles, bilinear CPU heights, 512 packed texture plus cubic-weight four-sample contour reconstruction differ. Texture coordinates use xz/world+.5 against endpoint-generated samples; use consistent texel-centre mapping and surface accuracy tests. The packed RG decode is linear, so do not falsely diagnose byte-boundary interpolation corruption. Test mesh-vs-query error, map shoreline and lake intersection. Fictional elevations are authored labels; landmark consistency needs checking, not claiming real-world mapping.
5. **Pacing / reversibility:** position derivative continuous but travel speed varies over 2x. Use arc-length/shot timing with bounded velocities, angular acceleration and transition windows. The current time clamp .05 slows catch-up under load. CSS 420ms independently timed chapter fades and threshold polarity changes can disagree with scroll state. Tie visual overlays to progress; preserve exact reverse pose; remove contradictory timing. Don't change viewport scale during travel.
6. **Environmental movement:** `shouldAnimateAmbient=false` and `uTime=progress*14` freeze water/clouds at rest. Intentional deterministic trade-off, but looks static in scenic moments. Keep camera/geography deterministic; optionally use independent subtle ambient clock at capped budget, pause offscreen, reduced motion and still, test camera/pose separately from pixel time. No continuous CPU/GPU activity in map/idle if not needed.
7. **Performance / resilience:** low-detail terrain 61,250 triangles, high 130,050, 512² texture, up to 32 reflection march steps per water pixel, seven shadow samples, multi-octave rock and three cloud layers. Expensive per-fragment work; current software Chromium is functional QA, not iPhone GPU cadence. Separate cartographic/terrain workload where possible, avoid rebuilding GPU programs for quality toggle; measure cold initialization, actual frame interval, dropped frames and GPU budget. Maintain A5 version coherence, depth clear, inert panels, native touch, reduced-motion/no-WebGL, recovery and stable buffers.
8. **UI:** persistent controls and scene text can create a technical overlay feel. Maintain accessibility while giving scenery more space, remove redundancy, quiet detail controls, contrast and focus. Still/no-WebGL needs all six chapters visible, no trapped controls. Actual keyboard and context restoration checks need expansion.
